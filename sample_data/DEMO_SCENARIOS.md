# Demo Scenarios — ecommerce_orders_2024

Тестовые сценарии для агентной системы аналитики данных.  
Датасет: `ecommerce_orders_2024.csv` — 1200 заказов, 22 колонки.

---

## Подготовка

Скопируй датасет в контейнер:

```bash
docker cp sample_data/ecommerce_orders_2024.csv analyst-mcp:/data/uploads/
```

---

## Сценарий 1 — Базовая загрузка и качество данных

**Промпт:**
> Загрузи CSV `/data/uploads/ecommerce_orders_2024.csv` и проверь качество данных

**Агенты:** `data_source_agent` → `data_quality_agent`

**Ожидаемый результат:**
- ~24 NULL в колонке `profit`
- ~10 выбросов `unit_price` (значения ×100)
- ~6 выбросов `qty` (500–2000)
- NULL в `delivery_date` / `delivery_days` для cancelled-заказов
- Рекомендации по очистке

---

## Сценарий 2 — SQL-аналитика

**Промпт:**
> Покажи топ-5 регионов по суммарной выручке и средний чек по каждому

**Агенты:** `sql_analysis_agent`

**Ожидаемый результат:**
- GROUP BY region, ORDER BY SUM(revenue) DESC
- Москва и СПб в топе за счёт регионального ценового коэффициента

---

## Сценарий 3 — Fraud detection

**Промпт:**
> Есть ли статистически значимая разница в доле мошеннических транзакций между методами оплаты? Сравни card и sbp

**Агенты:** `python_analytics_agent` → `statistical_test`

**Ожидаемый результат:**
- Chi-square тест, p < 0.05
- card: ~1.2% fraud, sbp: ~0.4% fraud — значимая разница

---

## Сценарий 4 — Визуализация ⭐ (хорошо для презентации)

**Промпт:**
> Построй три графика: (1) выручка по месяцам, (2) boxplot delivery_days по регионам, (3) heatmap корреляций числовых колонок

**Агенты:** `visualization_agent` × 3

**Ожидаемый результат:**
- Линейный график: пики в ноябре (+35%) и декабре (+50%)
- Boxplot: Красноярск и Новосибирск с большим медианным delivery_days
- Heatmap: сильная корреляция `product_weight_kg` ↔ `delivery_cost`

---

## Сценарий 5 — Сегментация клиентов

**Промпт:**
> Сделай кластеризацию клиентов по qty, revenue и discount_pct. Сколько кластеров оптимально? Опиши каждый кластер

**Агенты:** `transformation_agent` (агрегация по customer_id) → `python_analytics_agent` → `cluster`

**Ожидаемый результат:**
- 3–4 кластера: крупные B2B, премиум B2C, бюджетные покупатели
- StandardScaler + KMeans

---

## Сценарий 6 — LTV-анализ (цепочка агентов)

**Промпт:**
> Найди топ-20 клиентов по суммарной выручке. Для каждого покажи: регион, сегмент, любимую категорию и количество заказов

**Агенты:** `sql_analysis_agent` → `transformation_agent` → `result_formatter`

**Ожидаемый результат:**
- Таблица с агрегированными данными по customer_id
- Тест на многошаговую логику (multi-step reasoning)

---

## Сценарий 7 — Полный аналитический отчёт ⭐⭐ (главная демо-сцена)

**Промпт:**
> Подготовь полный аналитический отчёт по датасету продаж: ключевые метрики, проблемы качества, топ-инсайты, рекомендации. Включи 3 графика

**Агенты:** все агенты в цепочке → `reporting_agent`

**Ожидаемый результат:**
- Executive summary от LLM
- Секции: обзор данных, качество, аналитика, визуализации
- Финальный Markdown-отчёт сохраняется как артефакт

## Известные дефекты датасета

| Колонка | Проблема | Количество |
|---|---|---|
| `profit` | NULL значения | ~24 строки (~2%) |
| `unit_price` | Выбросы (×100) | ~10 строк |
| `qty` | Аномально большие значения | ~6 строк |
| `customer_rating` | NULL для non-delivered | закономерно |
| `delivery_date` | NULL для cancelled | закономерно |

## Интересные паттерны

| Паттерн | Как проверить |
|---|---|
| Сезонность: ноябрь/декабрь в 1.5× | `visualization_agent` → line chart по месяцам |
| Москва/СПб дороже регионов на 40–60% | `sql_analysis_agent` → AVG(unit_price) GROUP BY region |
| B2B_Medium: qty в ~5× выше B2C | `python_analytics_agent` → describe по сегментам |
| Fraud выше у card vs sbp | `python_analytics_agent` → statistical_test |
| weight_kg коррелирует с delivery_cost | `python_analytics_agent` → correlation |
