# ADR-001: Orchestrator Kernel Architecture

## Status
Accepted

## Context
Нужен управляемый оркестратор для выполнения аналитических сценариев без хаотичного поведения автономного агента. Требуется расширяемость через capability, изоляция провайдеров и безопасная работа с PII.

## Decision
1. Оркестратор реализуется как deterministic kernel: жизненный цикл задаётся кодом и графом, а не свободным loop LLM.
2. Расширение возможностей выполняется через capability registry с явными контрактами и адаптерами.
3. LLM provider isolation обязательна: ядро не зависит от конкретного провайдера, интеграция скрыта за adapter-слоем.
4. PII не обрабатывается внутри kernel; используется внешний provider gateway для outbound-вызовов к публичным LLM.

## Consequences
- Повышается воспроизводимость и управляемость исполнения.
- Новые tools/providers добавляются без изменения core runtime.
- Снижается риск утечек чувствительных данных в публичные модели.
- Добавляется необходимость поддерживать контракты registry/adapters и внешний PII gateway.
